# Inspector

WaOS's inspector, a program holding the inspector role, which it asks for by calling `wasdk::inspect` (wasdk's `inspector` feature): WaOS asks its user at its start whether it may see what other programs do, and starts it only with the role granted. It lists the programs on this device, itself among them, those that used something guarded lately first, each with its icon, read as its row is first shown and drawn with Waft's `Image::memory`, its version, whether it runs, when it last used something and what (Camera, Network, Files…). The list is read again at each change the device tells: a program installed or removed, started or ended.

A program's page is layered (decisions 14–16 of `docs/proposals/2026-11-15-inspector-roles-and-compatibility.md`), summary first and detail on demand, as the inspector design's mockups draw it. Its header names the program and whether it runs, with its commands on the right: Start inspected, or Restart inspected and Stop. Its first tab is the report, what it did over the last seven days: what WaOS refused, summed in one bar; each kind of access it used, a card row each, with a strip of the days, bars by count with refusals stacked in red, and a way on to its live panel; the kinds it did not use, in one line; the domains it contacted, in a table; and the questions it put. The other tabs are the live panels, as Chrome DevTools has them, each a table of what the program does while it is chosen: Network (lookups, connections, requests joined to their responses), Files (opens and changes, where each path is on this computer), Storage (the folders it sees at its own paths, a tree of what they hold, read as its own access would and never outside a mount), Access (what it reaches that its user decides: the camera and the microphone, the clipboard, links, notifications, the questions it puts and their answers, the machines and commands), Output (its standard output and errors, a line each) and In use (what it uses now: files open, connections with what they moved, captures). A panel filters its rows by text and by kind, shows the row selected in a detail pane beside its table, a refused one with the setting that refused it, and says in its status bar whether it listens and what it heard. While a program is chosen, every live panel listens, from when it is chosen or from its first instruction, so a tab switch shows what its panel has heard and nothing is read again; each keeps its last 2,000 rows and keeps them once its program ends. Each tab's badge is how many rows its panel holds, in red where any of them was refused, so the badge and the list always agree; the report keeps its seven-day picture, and Storage is a folder of its own with no count. Nothing listens while no program is chosen. Start inspected starts the program held before its first instruction until every panel listens, so launch-time events, the camera opening, are caught (decision 18); Stop ends it, since a program the inspector started has no `cargo waos run` to end it (decision 19).

The app is in Waft's three layers. `logic` is plain Rust, tested alone: what the days say (`activity`, `report`), each panel's log, which turns what it hears into changes of its typed rows, an event at a time (`panels`), and what the detail pane says of any row (`detail`). `state` holds the entities, one a feature: the programs and the one chosen, the selection of the list's `ItemsViewSource`, which the entity owns (`programs`); the chosen program's page, its tab and its panels (`page`); and each panel, its rows in a `TableViewSource` that each event changes by one insert or update, its filter, and its streams, which it drops at once as it stops (`panel`). `ui` is the widgets, thin: Fluent's from 600 logical points wide, the list an `ItemsView` beside the page, its tabs a `SelectorBar`, each panel a `TableView` with `InfoBar`s, `Expander`s and `FontIcon`s; narrower, as on a phone, Cupertino's: the list, then the report, then each panel, a page each with a way back, filtered by a `CupertinoSearchTextField` and a `CupertinoSegmentedControl`.

- **Takes:** `wasdk` with its `inspector` feature; `wasdk-adapter-waft`, Waft, its Fluent and Cupertino kits; `waos-activity`; `futures`, for ending a panel's streams; `indexmap`, for Cupertino's segmented control.
- **Provides:** the program `dev.waos.inspector`, named Inspector.
- **Used by:** whoever wants to see what their programs do.

```sh
cargo waos run -p inspector
cargo waos set role.inspector allow -p inspector   # answered ahead, from its next start
```

What reads as code, URLs, paths, addresses, times, sizes and the Output panel's lines, is drawn in Cascadia Mono, Microsoft's fixed-width font, carried in `assets/fonts/CascadiaMono-Regular.ttf` under the SIL Open Font License 1.1 (`assets/fonts/OFL.txt`) and registered with Waft at start (`code_font`).

`icon.png` is WaOS's default program icon for now, until the app has one drawn as the others are.
