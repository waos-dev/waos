# wasdk

What programs are written with: the generated bindings of the WIT packages `wasdk:platform` and `wasdk:media`, under the program's world in `wasdk:program`, passed through, and what generation cannot produce. Each module is the interface of that name in `wit/` as wit-bindgen `0.62.0` generates it: records and enums as the WIT names them, a resource as a struct with methods and its `constructor` as `new`, a plain function as a function of the module, a `borrow<T>` parameter as `&T`, `async func` as `async fn`, `stream<T>` as a `StreamReader<T>` read with `next().await`, or many items at once with `read(buffer).await`, whose `StreamResult` says whether the writer is gone, a stream the program gives made with `wit_stream::new` and written through its `StreamWriter<T>`, and `future<T>` as a `FutureReader<T>`, awaited for its value, one the program gives made with `wit_future::new` and written through its `FutureWriter<T>`. No hand-written wrapper over a generated type; the SDK pins one wit-bindgen per release.

- **Takes:** its own copy of the WIT, `wit/` beside `src/`, which `cargo xtask sync-wit` copies from the repository's `wit/`, the one edited: `wasdk:program`'s `inspector-base` world, the program's world without the `wasi:cli/run` Rust's `std` exports, over the `wasdk:platform` and `wasdk:media` packages, and `wasdk:inspect`, the inspector role's, which a component imports only where it calls it, with their WASI and `wasi:webgpu` dependencies; `wasdk-macros`, for the entry macros it re-exports; wit-bindgen's runtime, which every call runs on; `inventory`, where each `#[wasdk::worker]` registers its entry.
- **Provides:** `wasdk::views`, `wasdk::screens`, `wasdk::system`, `wasdk::windows`, `wasdk::lifecycle`, `wasdk::fonts`, `wasdk::permissions`, `wasdk::trust`, `wasdk::clipboard`, `wasdk::menus`, `wasdk::audio`, `wasdk::file_dialogs`, `wasdk::opener`, `wasdk::notifications`, `wasdk::machines`, `wasdk::file_watching`, `wasdk::media_players`, `wasdk::media_assets`, `wasdk::image_codecs`, `wasdk::video_frames`, `wasdk::hardware_buffers`, `wasdk::gpu_interop`, `wasdk::cameras`, `wasdk::caption_settings` and `wasdk::workers`, the twenty-five interfaces of the `program` world; with its `inspector` feature, `wasdk::inspect`, `wasdk:inspect`'s `devices`, `audit` and `trace`, which a program calls to ask for the inspector role, granted by its user at its start; `wasdk::webgpu`, `wasdk::monotonic_clock`, `wasdk::system_clock`, whose `instant` a notification is scheduled at, `wasdk::filesystem`, `wasi:filesystem/types` 0.3, whose `descriptor` a machine's root and a watched folder are, `wasdk::preopens`, `wasi:filesystem/preopens` 0.3, the root `/` a program opens its own folders and its mounts from, `wasdk::http`, WASI 0.3's HTTP client, and `wasdk::sockets`, WASI 0.3's sockets, the WASI interfaces it imports beside `std`'s; `#[wasdk::main]`, which also exports the program's `worker-entry`; `#[wasdk::worker]`; `wasdk::keys::logical` and `wasdk::keys::physical`, Flutter's names of the numbers a key event carries, `u64` constants such as `logical::ARROW_LEFT` and `physical::KEY_A`, with the logical planes' masks, transcribed from Flutter's generated `keyboard_key.g.dart` by `keys/transcribe.py` and under Flutter's BSD licence, `keys/LICENSE`; `wasdk::spawn`, a task on the program's executor; `wasdk::block_on`, which runs a future to its end where the code that needs its answer cannot await, as a library's synchronous callback, Typst's asking for a font, cannot; `wasdk::yield_async`, which lets the program's other ready work, and the events of its other streams, go before the task goes on; `StreamReader`, `StreamResult`, `StreamWriter`, `wit_stream`, `FutureReader`, `FutureWriter` and `wit_future`, the runtime's types the signatures name and what makes a stream or a future the program gives. Builders where Rust has a strong idiom, such as `Command` mirroring `std::process::Command`, come with the capabilities that need them.
- **Used by:** programs, which depend on `sdk/` only, built for `wasm32-wasip3`; `wasdk-wgpu`, which puts wgpu over `wasdk::webgpu`; `wasdk-adapter-waft`.

```rust
use wasdk::views::{self, ViewChange};

#[wasdk::main]
async fn main() {
    let mut changes = views::view_changes();
    for view in views::views() {
        println!("given view {}", view.id());
    }
    while let Some(change) = changes.next().await {
        if let ViewChange::Added(view) = change {
            println!("view {} arrived for request {:?}", view.id(), view.request_id());
        }
    }
}
```

A view's `ViewEvent::Key` carries a `KeyInput`, whose `event` is a `KeyEvent` in Flutter's `KeyData` vocabulary: `logical`, what the key means under the current layout, a character key's lower-case code point and any other key Flutter's number for it, and `physical`, where the key is, its USB HID usage. `wasdk::keys` names both, so a program compares with names rather than numbers it might write wrong: `event.logical == keys::logical::ARROW_LEFT`, `event.physical == keys::physical::KEY_W`. A key event names no modifiers, as `KeyData` names none: a program keeps which are held from the modifier keys it is sent, `logical::SHIFT_LEFT` and `logical::SHIFT_RIGHT` and the like, never `logical::SHIFT`, which stands for either in Flutter's maps and is never sent. `builtin-apps/model-viewer`'s `src/egui_view/keys.rs` does both for egui.

What the user set is `wasdk::system`'s, each with its change on `system::changes()`: light or dark, the languages, and the time zone, `system::time_zone()`, its IANA name, `Europe/Paris`, and `system::utc_offset(system_clock::now())`, how far the user's clock is from UTC at an instant, in nanoseconds, which a program adds to the instant for the time the user sees; both none where the system names no zone. `examples/survey` prints them.

A program that goes back within itself, as an app with pages does, says so on its view with `view.set_handles_back(true)`, and hears the user's Back, Android's back button and gesture, as `ViewEvent::PopRoute` while it does; it says `false` once it has nowhere left to go back to, and the platform then does its own with the press: in WaOS's deck on a phone, it leaves the program for the home, the program keeping its tab and running on. A view starts not handling Back. A program cannot be asked on the spot, so it says in advance, as an Android app registers for Back only while it wants it. `examples/back` goes back through pages this way, and `examples/waft-back` shows a Waft app doing it with no code of its own.

A view says what the system's bars drawn over it look like, the status bar and Android's navigation bar, with `view.set_overlay_style(style)`, an `OverlayStyle` whose `status_bar_icons` and `navigation_bar_icons` are `Some(system::Brightness::Dark)` over a light page and `Light` over a dark one, and whose `status_bar_contrast_enforced` and `navigation_bar_contrast_enforced` say whether the system may put a scrim behind each bar. A field left out keeps what was said before, and a view starts with the platform's style. It is Flutter's `SystemUiOverlayStyle` without the bars' colours; a Waft app says it with no code of its own, from what it draws under the bars. A desktop, which draws no bars over a view, ignores it.

A program's network is `std::net`'s, over WASI 0.3's sockets, which block the program while they wait; `wasdk::sockets`, WASI 0.3's sockets, the same sockets awaited: `TcpSocket::create`, `connect(address).await`, `send(stream)` and `receive()` as streams, `UdpSocket`'s `send` and `receive` awaited, and `ip_name_lookup::resolve_addresses(name).await`; and `wasdk::http`, WASI 0.3's HTTP client, whose `client::send(request).await` answers a `Response` without stopping the program, its body a stream read with `Response::consume_body`, and which WaOS sends through the system's proxy with the system's check of the server's certificate, following no redirect: a redirect is answered to the program, which asks its `location` itself if it wants to. A request is cancelled by dropping what `send` answered before it resolves, and a body by dropping its stream. What a program reaches is what its user allows: the internet under the network switch and its rule of domains, this computer and the local network under the local-network switch. `localhost` and every name under it, such as `app.localhost`, are this computer on every system, as in a browser: WaOS answers them with `::1` and `127.0.0.1` without asking the system, under the local-network switch whatever the rule of domains says. Each switch is read at each use, so a switch turned off refuses the next lookup, connection or request while a connection open carries on. A refused lookup or connection fails with `ErrorKind::PermissionDenied` through `std::net` and `access-denied` through `wasdk::sockets`, a refused request with `HTTP-request-denied`, a certificate the system does not trust with `TLS-certificate-error`. `wasdk::trust` checks a server's certificate chain as the system does, for a program that brings its own TLS. `examples/network`, `examples/fetch` and `examples/trust` are programs that use them.

A program's files are `std::fs`'s, which WaOS serves. The program sees one root, `/`, holding its own folders, `/data` for what it keeps, `/cache` for what it keeps that may be thrown away, and `/tmp`, a folder of its own that goes when it ends, crash or not, which `TMPDIR` names, and the folders the user mounted for it, each at a path inside it, read-only or writable; a folder above them lists only what is mounted under it, and a path outside them is not found. A folder the user mounts or takes away applies at the program's next call, and a file it opened stays open. Writing where a mount is read-only fails with `ErrorKind::ReadOnlyFilesystem`, a path leaving its mount, by `..` or a symlink, with `PermissionDenied`, and changing the folders above the mounts with `ReadOnlyFilesystem`, `AlreadyExists` or `ResourceBusy`. `examples/files` is a program that uses them. Rust's `std::env::temp_dir()` panics on WASI whatever `TMPDIR` says, a gap of `std`'s, so a program reads `TMPDIR` itself, and one on the `tempfile` crate calls `tempfile::env::override_temp_dir(Path::new("/tmp"))` once, before its first temporary file.

A program hears what changes in a folder it holds with `wasdk::file_watching`: `watch(&folder, recursive, latency_ms).await` takes the folder's `wasdk::filesystem::Descriptor`, one of its own folders or mounts opened from the root `wasdk::preopens::get_directories()` answers, `root.open_at(PathFlags::empty(), "data".to_owned(), OpenFlags::DIRECTORY, DescriptorFlags::READ).await`, or a machine's root or a folder opened from it, and answers, once the system watches it, a `StreamReader<Vec<Change>>`, each batch the changes of at most `latency_ms` after its first: `Created`, `Modified`, `Removed`, `Renamed((from, to))` where the system pairs a rename's ends, inotify and Windows, `Other` where it says nothing more, as FSEvents for each end of a rename, and `Rescan`, of a path or of everything, where changes were lost. Each path is relative to the folder, its names joined by `/`, the folder itself `.`. `recursive` watches everything under the folder, never a symlink's target; without it, the folder's own entries. Dropping the stream ends the watch. A folder above the mounts, the root among them, is `ErrorCode::Unsupported`, and a file `ErrorCode::NotDirectory`. `examples/file-watching` uses it.

A program's clipboard is `wasdk::clipboard`'s, the platform's one clipboard, which every program shares. What is on it, and its changes, the program sees while one of its views has the focus, its own copies among the changes: items, each offered in MIME types, the most faithful first, read one type at a time, a read failing with `changed` once anything has replaced what was listed. A copy gives each form's content at once as a stream, by a file's path inside the program, which WaOS writes as the file's path on the machine, or promises it, a promised form or file produced when someone pastes it, through the requests of the `source` the write answers, until another copy replaces it, each request answered with a stream and a `done` saying whether the content was made whole. WaOS thaws a frozen program to answer, and fails a paste whose form is not given whole within five seconds, whose file is not begun within them, or whose `done` does not say ok. A program's promises end with it, so one that ends on its own first calls `flush`, which asks for every form its copy still promises, files aside, and keeps what it gives for later pastes; WaOS asks the same before it stops a program. Reading is under the `clipboard-read` switch and writing under `clipboard-write`, each checked as it is made. The user's own commands come as a view's events and are free of the switches: `copy` and `cut` carry a `copy-request`, which writes once, and `paste` the clipboard as the user pasted it, read until anything replaces it, a file it names mounted read-only at its own path as its `text/uri-list` is read; `edit` carries undo, redo, select-all or delete. `examples/menus` answers them.

A program's sound is `wasdk::audio`'s, Web Audio's graph named as the web names it: `audio::get_audio()` answers the platform's sound, none where the program was given none; `audio.new_context(AudioContextOptions::new())` an `AudioContext`, which plays its graph, and `OfflineAudioContext::new(channels, length, sample_rate)` one which renders its graph into the buffer `start_rendering()` resolves to. Params, `AudioParam`, carry their automation on the base's `current_time()`, in seconds, and a source's `ended()` resolves once it has stopped. The platform renders the graph on its own thread, so what a program scheduled plays out while it waits or is frozen, and a program is not frozen while it plays, a source scheduled ahead counting from its start. Where the web takes an element or a stream, the platform has inputs of its own: `create_stream_input(channels)`, whose `write` takes interleaved samples and waits only while they are a tenth of a second ahead of what plays, and `open_microphone()`, which asks the user at its first use and answers `not-allowed` unless the user allows it, the platform showing that the program records while it holds the microphone. An output other than the default is one the user picks in the platform's picker, `audio.select_audio_output()`, and the context's `set_sink_id` moves onto it. A program does parallel work on workers with `wasdk::workers`, other instances of its own code, each on a thread of its own, sharing no memory with it and exchanging messages, each a `Vec<u8>`, as the web's workers do. A worker is an `async fn` marked `#[wasdk::worker]`, in the program's own crate, of its inbox, a `StreamReader<Vec<u8>>` of what the program sends it, and its outbox, a `StreamWriter<Vec<u8>>` of what it sends back; the attribute registers it under its name, which the constant beside it holds (`COMPILE_ENTRY` for `compile`). `workers::get_workers()` answers none where the program may have none; `workers.start(COMPILE_ENTRY.to_owned(), inbox).await` starts one in a new instance, its inbox the reading end of a `wit_stream::new()` the program writes, and answers the `Worker` once the new instance has accepted the entry, `WorkerError::UnknownEntry` for a name the program has no worker of; `worker.messages()` is what it sends, once, and `worker.finished().await` when it ended, with why where it trapped; dropping the `Worker` ends it where it stands. What one side writes waits until the other reads it. `available_parallelism()` says how many threads the machine runs at once. A worker has the program's files, network, machines, fonts, screens, caption settings, media assets, image codecs, clocks, random numbers and WebGPU, under the program's grants, and nothing of its user's side: no views, windows, menus, clipboard, dialogs, notifications, sound, players or cameras, each answering as on a platform without it, and no requests to end or to open, whose streams end at once. All of a program's workers read its clock, freeze with it, count in what it costs and end with it. `#[wasdk::main]` exports the program's `worker-entry` whether or not it has workers, so a program without them writes nothing. `examples/workers` uses them, and Documents typesets on one.
