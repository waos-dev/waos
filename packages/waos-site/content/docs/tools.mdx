title: The tools
description: Every cargo waos command, and when to use it.
---
`cargo waos` is the one tool: `cargo install waos-cli` installs it, and `cargo waos <command> --help` says everything about a command. Every command about a program runs in its package's folder, or names the package with `-p <package>`; elsewhere it stops with "could not find `Cargo.toml`".

## Make, build, ship

- **`cargo waos new <name>`** writes a new app in a folder of its name: a WinUI app, for desktops and phones; `--template cupertino` for one meant for phones alone. Inside a cargo workspace, the app becomes one of its members, as `cargo new` makes one.
- **`cargo waos build`** builds the app as a component, for `wasm32-wasip3`, at `target/waos/<profile>/<package>.wasm`; `--release` optimizes it. Use it until the app compiles.
- **`cargo waos run`** builds the app and runs it in the WaOS on this machine, starting WaOS when none is running, as the program its id names, with that program's settings and folders. What the app prints, and its panics, come to this terminal; Ctrl-C stops it. `--env NAME=VALUE` gives the app a variable for this run alone, such as `--env RUST_LOG=debug`; nothing of the shell's environment is passed.
- **`cargo waos package`** builds the release component and writes it as a package signed with your key, at `target/waos/<id>-<version>.wapk`, listed in `target/waos/index.json`, from the id, name and icon of the package's `[package.metadata.waos]`.

> A run lives as long as the `cargo waos run` that started it: leave it running, in a terminal of its own, while the other commands reach it, and start it so that the shell it runs in stays. A second `cargo waos run` of the same app replaces the first, which prints that it was replaced.

## See it and use it

These reach the app a `cargo waos run` is running; they never start WaOS. Each input is made by WaOS and handed to the app as its user's would be: the system never sees it, the real pointer does not move, and the command returns once the window has shown its next picture. Windows are numbered from 1, in the order they opened, and `--window <n>` picks one.

- **`cargo waos screenshot`** writes each window's last picture as `target/waos/screenshots/<package>/window-<n>.png`, and prints each window's number, title and size in pixels; `--out <file>` writes one window's picture there, and `--out <folder>/` all of them. Read the PNG to see the app.
- **`cargo waos tap --at x,y`** clicks there. **`press --at x,y`** holds the button a second, or `--duration <ms>`. **`drag --from x,y --to x,y`** moves in 10 steps over 300 ms (`--steps`, `--duration`, and `--hold <ms>` before the first move). **`scroll --at x,y --by dx,dy`** scrolls as a mouse wheel does, a positive `dy` towards the end.
- **`cargo waos type "<text>"`** enters text where the app edits, as an input method does. **`cargo waos key <chord>`** presses a key or a chord: `enter`, `escape`, `tab`, `cmd+s`, `shift+tab`.
- **`cargo waos resize --to 390x844`** sizes the window so the app draws that many points, to see the layout at a phone's width, and prints the size it took and the scale.

> `tap`, `press`, `drag` and `scroll` take the screenshot's pixels; `resize` takes points, which are pixels over the window's scale, 2 on a Retina screen: `--to 390x844` gives a screenshot of 780 × 1688. The window system may keep a window within the screen, so a size larger than the screen can give a smaller window: the printed size says what it took.

> A key the app leaves goes nowhere, where a real one would go on to the menu bar: `key cmd+q` does not quit.

## Answer ahead

WaOS asks its user before a program uses a camera, the microphone or notifications, and shows a dialog when it asks for a file or a machine. Each question is a row in the program's settings, and a row set ahead is answered without asking, so a run never waits for a person.

- **`cargo waos settings`** lists the rows, with the machines and outputs they can be set to.
- **`cargo waos set <row> <value>`** sets one: `camera allow`, `camera simulated` (a test pattern from WaOS, on macOS and Android), `microphone simulated` (a quiet beep), `notifications allow`, `network off`, `save-file /tmp/out.pdf`, `open-file /path/to/notes.md`, `machine this-computer`, and `ask` to ask again. `cargo waos set --help` lists every row and its values.

> Set an answer before the app asks. While WaOS is asking, the input commands are refused, saying WaOS is asking over the app's windows, and a screenshot does not show the question; a `set` then changes the row without answering the question already open, so stop the run, set the row, and run again.

> A path is made whole against this folder, and WaOS resolves any `..` in it before keeping it. A file to open must exist, and a file to save must be in a folder that exists.

## Look inside

- **`cargo waos inspect summary`** prints what the app did with what it was allowed, a day a line as JSON, newest first (`--days <n>`, 7 by default).
- **`cargo waos inspect active-uses`** prints what it uses now, then each change, until Ctrl-C or its end.
- **`cargo waos inspect <capability>…`** traces `network`, `files`, `clipboard`, `camera`, `microphone`, `machines`, `permissions`, `links`, `notifications` or `output`, or `all`, an event a line, as they happen.

## The docs

- **`cargo waos docs`** prints the map of these pages, a line a page, in the order to read them. **`cargo waos docs <page>`** prints one, as `cargo waos docs guide/network` or `cargo waos docs network`; a link `/docs/<page>` in a page is `cargo waos docs <page>`. **`cargo waos docs --search <text>`** prints each line that holds the text, as `<page>:<line>: <text>`. The docs are those of the version the app builds with, its `wasdk` in its `Cargo.lock` (outside an app, the command's own), downloaded the first time from that version's GitHub release into the user's cache folder and read offline after; where they cannot be downloaded, waos.app's latest docs stand in, and the command says so.
- **`cargo waos skill install`** writes the docs as a skill an agent loads when it builds a WaOS app: a folder `waos`, with `SKILL.md`, the playbook, and `docs/`, in Claude Code's personal skills folder, `~/.claude/skills`, or in the skills folder `--dir` names. It prints where it wrote. Install it again after updating the app's `wasdk`, so the docs match it.
