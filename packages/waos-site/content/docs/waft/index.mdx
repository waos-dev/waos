Waft is Flutter's framework ported to Rust, with three kits of controls: WinUI's, Cupertino's and Material's. Its widgets have Flutter's names and behave as Flutter's do, so Flutter's documentation tells what a widget does. These pages say how an app is put together, and where Waft differs.

**`Ref` models Flutter's objects and their relations; `Entity` is for writing the app's logic.** A text field's controller, a focus node, a route or an animation is a Flutter object, made by Waft and kept by a `Ref`. The app's own data, and the code that changes it, live in entities, which widgets read in `build`. So most widgets are `StatelessWidget`s. A `StatefulWidget` is for the rare widget that owns a Flutter object of its own, such as a text field's controller ([State](/docs/waft/state)).

## A WaOS app

A WaOS app is a Waft app run by `wasdk_adapter_waft`; `cargo waos new` writes one of this shape:

```rust
// Waft's `StatefulWidget::State` takes `self: Handle<Self>`, which needs nightly's arbitrary_self_types.
#![feature(arbitrary_self_types)]

use std::time::Duration;

use waft::*;
use waft_winui::*;

#[wasdk::main]
async fn main() {
    wasdk_adapter_waft::run(start).await;
}

fn start(app: &mut App) {
    let notes = app.new_entity(|_| Notes {
        added: Vec::new(),
        now: DateTime::now(),
    });
    let clock = notes.clone();
    Timer::periodic(app, Duration::from_secs(1), move |app, _each| {
        clock.update(app, |notes, cx| {
            notes.now = DateTime::now();
            cx.notify();
        });
    });
    let window = WindowConfig { size: [1080.0, 780.0], ..WindowConfig::default() };
    run_app_with(app, widgets_app(notes), window);
}

/// `FluentApp` brings WinUI's theme, its icon font, its overlay and its page route builder.
fn widgets_app(notes: Entity<Notes>) -> WidgetRef {
    FluentApp::new()
        .debug_show_checked_mode_banner(false)
        .home(Home { notes })
        .into_widget()
}
```

`run_app_with` asks for a window configured so, on Android a task of its own; in WaOS's tabs on a phone, which give the app its tab's view, the configuration goes unused. `run_app(app, widget)` is the same with the default window. `FluentApp` installs WinUI's theme, icon font and route builder for you (and `CupertinoApp` and `MaterialApp` do the same for their kits); `debug_show_checked_mode_banner(false)` hides Flutter's DEBUG ribbon in the top-right corner. The program's `rust-toolchain.toml` pins the nightly toolchain with `wasm32-wasip3`, which rustup fetches on the first build.

## Logic, state and UI

An app is three layers:

- **Logic:** the app's rules as plain Rust, which names neither `App` nor `Entity`, so it runs and is tested on its own.
- **State:** entities over the logic, where `App`, `Entity`, tasks and timers are used. Reading an entity in `build` subscribes the widget to it, and `cx.notify()` rebuilds every widget that read it.
- **UI:** thin widgets, which read entities in `build` and call the state's methods from callbacks.

A clock that ticks each second, and loads a quote when asked:

```rust
use std::time::Duration;

/// Logic: plain Rust.
#[derive(Default)]
struct Clock {
    seconds: u64,
    quote: Option<String>,
}

/// State: an entity over the logic, and the work that changes it.
#[derive(Clone, Debug)]
struct ClockModel {
    clock: Entity<Clock>,
}

impl ClockModel {
    fn new(app: &mut App) -> ClockModel {
        let model = ClockModel { clock: app.new_entity(|_cx| Clock::default()) };
        let clock = model.clock.clone();
        Timer::periodic(app, Duration::from_secs(1), move |app, _each| {
            clock.update(app, |clock, cx| {
                clock.seconds += 1;
                cx.notify();
            });
        });
        model
    }

    /// Loads a quote in a task, while the window goes on drawing.
    fn load_quote(&self, app: &mut App) {
        let clock = self.clock.clone();
        app.spawn(async move |cx| {
            let quote = fetch_quote().await;
            cx.update(|app| {
                clock.update(app, |clock, cx| {
                    clock.quote = Some(quote);
                    cx.notify();
                });
            });
        });
    }
}

/// Any future: an HTTP GET (Network), a file, a worker's answer. Here, half a second's wait.
async fn fetch_quote() -> String {
    wasdk::monotonic_clock::wait_for(500_000_000).await;
    "Simple things should be simple.".to_owned()
}

/// UI: reads the entity in build, calls the model from callbacks.
#[derive(Debug)]
struct Home {
    model: ClockModel,
}

impl StatelessWidget for Home {
    fn build(&self, app: &mut App, _context: BuildContext) -> WidgetRef {
        let (seconds, quote) = {
            let clock = self.model.clock.read(app);
            (clock.seconds, clock.quote.clone())
        };
        let seconds = Text::new(format!("{seconds} seconds"));
        let quote = Text::new(quote.unwrap_or_else(|| "No quote yet".to_owned()));
        let model = self.model.clone();
        let load = Button::text("Load a quote", Listener::new(move |app| model.load_quote(app)));
        Column::new()
            .spacing(12.0)
            .children([seconds.into_widget(), quote.into_widget(), load.into_widget()])
            .into_widget()
    }
}
```

The app makes its model once, in `start`, and hands it to the widgets:

```rust
let model = ClockModel::new(app);
run_app_with(app, FluentApp::new().debug_show_checked_mode_banner(false).home(Home { model }).into_widget(), window);
```

> Each closure that keeps a handle takes a clone of its own: `let model = self.clone();` before `move`. A `Listener` may be called many times, so it cannot give away what it captured.

## Async work

An app runs on one thread, and its async work runs there as tasks:

- `app.spawn(async move |cx| …)` starts a task, which awaits any future, the platform's or wasdk's, and reaches the app again through `cx.update(|app| …)`. It starts once the current event is handled.
- `Timer::periodic(app, duration, |app, timer| …)` repeats every `duration` (firing once without replaying missed ticks when a frozen program thaws); `Timer::new(app, duration, listener)` fires once after `duration`. Call `cancel(app)` to stop either.
- `app.run_in_background(work)` answers a task with the work's result.
- A callback from outside the app, such as a system's observer, hands it work with `post` on the `AsyncApp` that `app.to_async()` answers.

> On WaOS a program has one thread, so `run_in_background`'s work runs on it too, after the current event, and long work still holds the window up. Work that long goes to a worker ([Workers](/docs/guide/workers)), started from a task.

## Names that differ from Flutter

Waft keeps Flutter's names; what changes is what Rust needs:

| Flutter | Waft |
| --- | --- |
| `Text('Hi', maxLines: 1)` | `Text::new("Hi").max_lines(1)`: a required argument is `new`'s, each named one a builder method |
| `Expanded(child: list)` | `Expanded::new(list)`: a required child is `new`'s argument; an optional one is `.child(…)`, as `Padding::new(insets).child(text)` |
| `children: [a, b]` | `.children([a.into_widget(), b.into_widget()])`: a child is a `WidgetRef`, which `.into_widget()` makes of any widget |
| `EdgeInsets.all(12)`, `EdgeInsets.symmetric(vertical: 8, horizontal: 16)` | `EdgeInsetsGeometry::all(12.0)`, `EdgeInsetsGeometry::symmetric(8.0, 16.0)`, vertical first: `Padding` and `Container::padding` take an `EdgeInsetsGeometry`, and an `EdgeInsets` becomes one with `.into()` |
| `size.width`, `offset.dx` | `size.width()`, `offset.dx()`: a Dart getter is a method |
| `FontWeight.w600`, `FontWeight.bold`, `Alignment.center` | `FontWeight::W600`, `FontWeight::BOLD`, `Alignment::CENTER`: a constant is in capitals |
| `Color(0xFF2196F3)` | `Color::new(0xFF2196F3)`, or `Color::from_argb(255, 33, 150, 243)` |
| `onPressed: () { … }` | `Listener::new(…)` of a closure taking `app`; a callback handed a value, as a switch's, is a closure taking `app` and the value, not an `Rc` |
| `Theme.of(context)` | `ThemeResources::of(app, context)`: every call is passed `app`, which holds all state |
| `setState(() { … })` | `self.set_state(app, …)`, with a closure that changes the state |
| a widget class | a struct that derives `Debug`, which every widget must, and implements `StatelessWidget` or `StatefulWidget` |
| the `Listener` widget, for raw pointer events | `waft_widgets::Listener`, from the `waft-widgets` crate; `waft::Listener` is the callback |

## Not in Waft

`FutureBuilder` and `StreamBuilder` (a task and an entity do their work), `AnimatedList`, `InteractiveViewer`, the `Router`, and accessibility. A panic in `build` ends the program, where Flutter paints its red error box.
