---
title: Fonts
description: Find the system's fonts, have their glyphs drawn, or read a font's file whole.
---

The fonts installed on the system, found as Skia's font manager finds them: the families, a family's faces, the face nearest a style, the face that covers a character, preferring the languages the program names, and the system's own interface font. Each is a `typeface`, one face in a font file, with its tables, outlines and colour glyphs left out: the engine draws a glyph's pixels or its path for the program, so a program that only shows text never holds a font file. A program that reads fonts itself, as a typesetter or an immediate-mode interface does, opens a face's whole file with `open-stream`: its bytes, their length, so it reserves the buffer once, and the face's index in the file.

## With wasdk

```rust
let regular = Style { weight: 400, width: 100.0, slant: Slant::Upright };
let face = fonts::match_character(None, regular, &["ja".to_owned()], '字').ok_or("no face")?;
// the font file whole, as Skia's openStream opens it
let FontFile { mut data, length, index } = face.open_stream();
let mut bytes = Vec::with_capacity(length as usize);
while bytes.len() < length as usize {
    let (result, read) = data.read(bytes).await;
    bytes = read;
    if result == StreamResult::Dropped { break; }
}
// parse bytes as the face at index, with read-fonts or the program's own font library
```

A library that asks for a font without awaiting, as Typst does, reads it with `wasdk::block_on`, as Documents does.

## With Waft

Nothing to write: Waft finds the system's faces through `fonts`, the system font among them, and the engine draws its glyphs.

## Where it's missing

A program given no fonts gets empty answers, as on a machine with none installed. `system-font` is none where the platform has no such notion. A font file opened is copied into the program's memory, its whole size in each program that asks.
