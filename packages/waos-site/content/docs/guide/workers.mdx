---
title: Workers
description: Run heavy work in parallel, off the window's thread.
---

A program has one thread, so work that takes long holds its window up while it runs. A worker is another instance of the program's own code, on a thread of its own, as the web's workers are: it shares no memory with the program, and the two send each other messages, each a `Vec<u8>`, over a stream each way. A worker is a function the program marks `#[wasdk::worker]`; the program starts it by its name, sends it work, and reads what it sends back, while its window goes on answering. Several workers run in parallel, as many at once as the machine has threads (`available_parallelism`).

## With wasdk

```rust
use wasdk::workers;
use wasdk::{StreamReader, StreamWriter, wit_stream};

// in the program's own crate; COMPILE_ENTRY, beside it, is its name
#[wasdk::worker]
async fn compile(mut inbox: StreamReader<Vec<u8>>, mut outbox: StreamWriter<Vec<u8>>) {
    while let Some(source) = inbox.next().await {
        outbox.write_one(render_pages(&source)).await;
    }
}

// in the main instance: workers::get_workers()
let (mut to_worker, inbox) = wit_stream::new();
let worker = workers.start(COMPILE_ENTRY.to_owned(), inbox).await?;
let mut pages = worker.messages().unwrap();
to_worker.write_one(source.into_bytes()).await;
let page = pages.next().await;
```

`start` answers once the new instance has taken the entry, `UnknownEntry` for a name the program has no worker of; the worker's function runs after. What one side writes waits until the other reads it. `finished` resolves once the worker has ended, and says why if it failed: a trap, as a panic is, or an exit with a code other than 0. Dropping the `Worker` ends it where it stands; dropping the writer of its inbox ends the stream it reads, so a worker reading until its inbox ends returns. A worker may start workers of its own. Messages are bytes: a program says what they hold, with serde and postcard for one, as Documents does.

## With Waft

Waft has no API for workers; start one from a task (`app.spawn`) and hand each reply to the app with `cx.update`.

## Where it's missing

A worker has the program's files, network, machines, fonts, clocks, random numbers and WebGPU, under the program's grants, with the screens, the system's settings (light or dark, the languages, the time zone), the caption style, hardware buffers, image codecs and media assets, so it can decode and encode pictures and read media; and none of what belongs to its user: no views or windows, no menus, clipboard, dialogs, opener, notifications, sound, players, frame readers or cameras, each answering as on a platform without it (`views` lists none and refuses a request with `unsupported`, a getter answers none), and the requests to quit and to open end at once in it, since they are the main instance's. A worker's machines are those the user granted: its `pick` asks nobody, and answers the machine set in the program's settings, or none. All of a program's workers read its clock, freeze with it when it is out of sight, count in what it costs and end when it ends. A program runs at most 64 workers at once, its workers' workers among them; `start` answers `Refused` past them. A worker's function is in the program's own crate, where its registration is linked.
