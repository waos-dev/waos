title: Network
description: Reach the network with sockets and HTTP, as the user allows.
---

The network as WASI gives it: an HTTP client, `wasdk::http`, WASI 0.3's, whose requests a program awaits; sockets a program awaits, `wasdk::sockets`, WASI 0.3's; and the sockets of Rust's `std::net`, WASI 0.2's, which block the program's one thread, its window with it, while they wait. What a program reaches is the user's to set in its settings in WaOS: the network, on for any domain unless the user limits it to some, and the local network (this computer, the local network and listening for connections), off unless the user turns it on. `localhost` and every name under it, such as `app.localhost`, are this computer on every system, as in a browser: WaOS answers them with `::1` and `127.0.0.1` without asking the system, so they fall under the local network, whatever domains the user limits the network to. WaOS sends HTTP through the system's proxy and checks a server's certificate as the system does; a program that brings its own TLS checks a server's chain with the system through `trust`.

## With wasdk

```rust
// wasdk::http: a request, sent and awaited; its body read as a stream
let (_no_trailers, trailers) = wit_future::new(|| Ok(None));
let (request, _sent) = Request::new(Fields::new(), None, trailers, None);
request.set_scheme(Some(&Scheme::Https)).unwrap();
request.set_authority(Some("example.com")).unwrap();
request.set_path_with_query(Some("/")).unwrap();
let response = client::send(request).await?;
let (_done, read) = wit_future::new(|| Ok(()));
let (body, _trailers) = Response::consume_body(response, read);
let page = body.collect().await;

// wasdk::sockets: a connection, awaited
let socket = TcpSocket::create(IpAddressFamily::Ipv4)?;
socket.connect(address).await?;
let (mut received, _) = socket.receive();

// std::net: blocks until it is done
let mut stream = TcpStream::connect(("example.com", 80))?;
```

A request whose future is dropped before it resolves is cancelled, its connection closed; to give up after a time, race `client::send` against `monotonic_clock::wait_for`. A body the program sends is a stream it writes, as `wit_stream::new` makes one; once a write comes back with something unwritten, the server is no longer reading, and a further write traps.

## With Waft

Waft has no API for the network; use `wasdk::http` or `wasdk::sockets` from a task, as above, so the window keeps drawing while a request is out.

## Where it's missing

WaOS answers a redirect rather than following it: the program reads its `location` and asks again, if it wants to. A request the user's settings refuse fails with `HttpRequestDenied` before anything is sent, a server whose certificate the system does not trust with `TlsCertificateError`; a lookup or a connection they refuse fails with `AccessDenied` through `wasdk::sockets` and `PermissionDenied` through `std::net`. Under a rule of some domains, an address with no name is refused. A switch turned off refuses new connections and requests; one already open stays. `permissions::network().request()` opens the switch's page in WaOS's settings for the user.

## Interface

`wasi:http/client@0.3.0`, `wasi:sockets@0.3.0` and `wasi:sockets@0.2.12`, with [`wasdk:platform/trust`](/docs/reference/wasdk-platform/trust) and the switches in [`wasdk:platform/permissions`](/docs/reference/wasdk-platform/permissions)
