The system's cameras, listed with which way each faces, opened once the user allows it, and run in one of a camera's formats. A running camera feeds the outputs it was started with: a preview on a composition layer, frames in a frame reader for the program to draw, and photos the system encodes. A frame says how it is shown, as the web's `VideoFrame` does: turned by its `rotation`, 0, 90, 180 or 270 degrees clockwise, then mirrored where `flip` says, as a camera looking at its user is. The system draws the preview turned, and a photo carries its turn in its EXIF.

## With wasdk

```rust
// cameras: cameras::get_cameras()
let first = cameras.list().await.into_iter().next().ok_or("no camera")?;
// asks the user the first time
let camera = cameras.open(first.id).await?;
let format = camera.formats().remove(0);
let outputs = CameraOutputs::new();
// a composition layer the view places
outputs.set_preview(&layer);
outputs.set_photos(format.photo_sizes[0]);
let session = camera.start(format, &outputs).await?;
// encoded by the system: photo.mime_type, photo.data
let photo = session.take_photo().await?;
// the turn of what is captured, which each frame's rotation says too
let turn = session.video_rotation_angles().for_horizon_level_capture;
```

A session gives two turns, as Apple's rotation coordinator does: the preview's, which the system draws it turned by, and what is captured's, which a photo carries in its EXIF and a frame as its `rotation`; they differ only while the device turns, and `video-rotation-angle-changes` hears each change. `set_upright_frames()` on the outputs asks for frames already turned and mirrored as they show, each with `rotation` 0 and `flip` false, which costs the system a turn of every frame.

## With Waft

```rust
use waft::ui::CameraOutputs;

let listing = available_cameras(app);
app.spawn(async move |cx| {
    let Some(camera) = listing.await.into_iter().next() else { return };
    let Some(opening) = cx.update(|app| open_camera(app, &camera)) else { return };
    // asks the user the first time
    let Ok(device) = opening.await else { return };
    let format = device.formats().remove(0);
    let starting = cx.update(|app| {
        let preview = app.platform().compositor().map(|compositor| compositor.make_layer(false));
        CameraSession::start(app, &*device, &format, CameraOutputs { preview, ..CameraOutputs::new() })
    });
    // CameraPreview::new(session) shows it in a widget
    let Ok(session) = starting.await else { return };
});
```

`CameraOutputs::upright_frames()` asks for upright frames, and `CameraSession::video_rotation_angle_for_horizon_level_capture(session, app)` reads the turn; a frame from a reader says its own with `rotation()` and `flip()`.

### Filtering frames with WebGPU

When you want to run a WGSL filter over live camera frames (using `wasdk-wgpu`, which targets `wgpu` 30), pass a `VideoFrameReader` in `CameraOutputs::frames` instead of a direct preview layer, import each frame's `HardwareBuffer` as a `wgpu::Texture`, render into a pooled output `HardwareBuffer`, and present it on a `CompositionLayer` displayed by `CompositionLayerView`:

```rust
use std::sync::Arc;
use std::sync::atomic::{AtomicBool, Ordering};
use waft::ui::image_codecs::{ImageErrorKind, PixelFormat};
use waft::ui::{CompositionLayer, HardwareBuffer, HardwareBufferUsage, Platform};

struct PooledSheet {
    buffer: Arc<dyn HardwareBuffer>,
    texture: wgpu::Texture,
    free: Arc<AtomicBool>,
}

/// Allocates a buffer for compositing: Apple allocates Bgra8, Android allocates Rgba8.
fn allocate_sheet(platform: &dyn Platform, device: &wgpu::Device, width: u32, height: u32) -> Option<PooledSheet> {
    let allocator = platform.hardware_buffer_allocator()?;
    let usage = HardwareBufferUsage {
        gpu_color_output: true,
        gpu_sampled: true,
        composer_overlay: true,
        ..HardwareBufferUsage::default()
    };
    for format in [PixelFormat::Bgra8, PixelFormat::Rgba8] {
        match allocator.allocate(width, height, format, usage) {
            Ok(buffer) => {
                let texture = platform.import_texture(buffer.as_ref(), device)?;
                return Some(PooledSheet { buffer, texture, free: Arc::new(AtomicBool::new(true)) });
            }
            Err(err) if err.kind == ImageErrorKind::Unsupported => continue,
            Err(_) => return None,
        }
    }
    None
}

// On each frame tick: sample the camera frame, run your WGSL pass into a free pooled sheet, and present.
fn present_filtered(
    platform: &dyn Platform,
    device: &wgpu::Device,
    layer: &dyn CompositionLayer,
    frame_buffer: &dyn HardwareBuffer,
    sheet: &PooledSheet,
    run_wgsl_pass: impl FnOnce(&wgpu::Texture, &wgpu::Texture),
) {
    let Some(input_texture) = platform.import_texture(frame_buffer, device) else { return };
    run_wgsl_pass(&input_texture, &sheet.texture);
    sheet.free.store(false, Ordering::Release);
    let free = Arc::clone(&sheet.free);
    layer.present(Arc::clone(&sheet.buffer), Vec::new(), Box::new(move || {
        free.store(true, Ordering::Release);
    }));
}
// Place `CompositionLayerView::new(Arc::clone(&layer))` in your widget tree.
```

Keep a small pool of `PooledSheet`s and pick one whose `free` flag is `true` (allocating another if none is free yet — never block waiting for `free`, as explained in [Compositing](/docs/guide/compositing#a-picture-that-changes)).

## On each system

- **macOS:** the system's cameras. After the user allows the program, macOS asks for WaOS the first time. Upright frames are offered.
- **Android:** the system's cameras. After the user allows the program, Android asks for WaOS the first time. A frame is turned by the sensor's orientation against the screen's, and both turns are that one. Upright frames are not: `start` answers `not-supported`. Android gives a camera one stream of photos, so a session that joins another program's takes its photos at the size the first set, or none where it set none.
- **Windows and Linux:** no cameras yet: `get-cameras` is none.
- **Simulated:** a program whose camera is answered simulated in its settings (`cargo waos settings set camera simulated`) gets WaOS's own camera in place of the system's, with no question and no device: "WaOS test pattern", at 640 by 480 and 1280 by 720, 30 frames a second, photos at the frame's size. It draws a red, green, blue and white square in its four corners, so a turned, mirrored or channel-swapped picture shows at once, a counter of the frame's number and a moving bar. It is on macOS and Android; elsewhere such a program sees no camera.

## Where it's missing

`get-cameras` is none where the system has none, and Waft lists no cameras. Opening a camera asks the user at its first use and answers `not-allowed` if they refuse. A camera another program runs keeps its format, and a later session joins it in that one (`session.format()`). A session is interrupted, giving no frames until it resumes by itself, with a reason where the system gives one, which macOS does not. Recording video is not offered to programs yet: Waft's `start_recording` fails.
