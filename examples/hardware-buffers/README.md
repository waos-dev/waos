# hardware-buffers

A program that draws into GPU memory of its own and shows it beside its canvas, and what the tests read a program's hardware buffers through WaOS from: with the system's hardware buffer allocator it says what the system refuses, `rgba8: unsupported` on Apple's systems or `bgra8: unsupported` on Android, and `16385x48: too-large`, a side past the largest texture, then allocates two buffers of 64 by 48 for drawing, sampling and showing, in the format the system allocates, the green one for reading back too, saying `allocated 2 buffers of 64x48`, and what the red one, asked for no reading back, can be used for, as the buffer answers it (`hardware-buffer.usage`): `red can be gpu-sampled, gpu-color-output, composer-overlay, cpu-read` on Apple's systems, which give a buffer the program allocates every use, and the same without `cpu-read` on Android, which gives a buffer what it was allocated for; through a texture it imports of each on its own device (`wasdk_wgpu::import_texture`, over `wasdk:platform/gpu-interop`), clears one red with a render pass and writes the other's pixels green with `write_texture`, submitting nothing after, since whatever reads or shows a buffer submits the program's writes first; reads the green one's pixels back, as `read 64x48 bgra8 premultiplied, first pixel [0, 255, 0, 255]` (`rgba8` on Android), the bytes as they are in memory; and encodes the red one as PNG through the system's hardware codecs, as `encoded image/png from 64x48`. Then, in a view of its own, it makes a composition layer on the system's compositor, presents the red buffer on it, saying `presented red`, places the layer at 16, 16 in its view, beside its canvas, which it clears grey, writing clear pixels where the layer shows after the clear is submitted, and presents its view; at each frame after, it presents the green buffer, saying `presented green` the first time, until the compositor is done with the red one, which it says as `red is back`, and asks for no frame after. It closes its window when asked, and ends when its view is gone. Where the system allocates no hardware buffers it says `hardware buffer allocator: none`, no hardware codecs `hardware image codecs: none`, and no compositor `no compositor`, drawing its canvas with no layer.

- **Takes:** `wasdk`, `wasdk-wgpu`, `wgpu`.
- **Provides:** a component, `target/wasm32-wasip3/debug/hardware-buffers.wasm`, from `cargo build -p hardware-buffers --target wasm32-wasip3`.
- **Used by:** the engine's tests, through `crates/waos/tests/programs`; whoever reads it for how a program allocates, draws, reads, encodes and shows a hardware buffer.
