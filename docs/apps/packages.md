# Packages

- **An app, or a tool.** An app has a UI; a tool is a command-line app with none. An app is a tool only when its manifest says `kind = "tool"`. ([manifest.rs](/crates/waos-package/src/manifest.rs))
- **An app can say what it's for.** An optional `category` in its manifest, one of Apple's App Store categories, files it under the same heading wherever it shows: WaOS's home, macOS's Apps, Linux's menus. An older WaOS ignores it, and a category a later WaOS adds reads as none. ([category.rs](/crates/waos-package/src/category.rs))
- **An app can say which kinds of file it opens.** Each `[[package.metadata.waos.file_associations]]` gives the extensions, without the dot, what the system calls such a file, and its MIME type where it has one; they travel in its manifest, and an older WaOS ignores them. ([file_association.rs](/crates/waos-package/src/file_association.rs))
- **A `.wapk` is the app, its icon, and its publisher's signature.** The signature covers the manifest, the component and the icon (256 px or more). Other files in it are ignored, so a later version of the format can add its own. ([waos-package](/crates/waos-package/src/lib.rs))
- **Nothing in a package is believed before its signature checks.** ([package.rs](/crates/waos-package/src/package.rs))
- **An update must come from the same publisher, and be newer.** WaOS trusts the key an app was first installed with; a package signed by another key is a different publisher and never replaces it. Any source can offer the update; the key decides, when the update is committed. ([manager.rs](/crates/waos-services/src/packages/manager.rs))
- **An install never half-happens.** Switching which version is current is the one step that installs, and moving the app's folder away the one step that removes, so a crash leaves the old install or the new one, never part of either. ([programs.rs](/crates/waos-services/src/packages/programs.rs))
- **What is installed is what was checked.** A package's bytes are taken into WaOS's own folder before anything reads them, and an install asked for one app refuses a package of another. ([manager.rs](/crates/waos-services/src/packages/manager.rs))
- **Removing an app removes all of it:** its data, cache, settings and activity record. ([manager.rs](/crates/waos-services/src/packages/manager.rs), [service.rs](/crates/waos-services/src/permissions/service.rs), [record.rs](/crates/waos-services/src/activity/record.rs))
- **An app's code compiles when it installs, not when it first opens,** as Android does, so the first open is fast: an install is done once its code is, and a component that does not compile is refused. The code lives in the installed version's own folder and goes with it; it is a cache: after a WaOS update changed the engine, or where the code no longer loads, the next open compiles it again, shown as Optimizing…, and fails only if the fresh code does not load either. ([manager.rs](/crates/waos-services/src/packages/manager.rs))
- **A development install sits beside the published app.** `waos install` installs from source as `<id>.development`, with its own data and settings and " (Development)" after its name. No package can take that id, so no update replaces it. ([programs.rs](/crates/waos-services/src/packages/programs.rs))
