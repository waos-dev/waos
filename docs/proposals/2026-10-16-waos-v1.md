# WaOS's first version: what it is, and how far it is

> Carried over from `../wasdk/docs/proposals/` on 2026-10-17, as written for the experiment, which is frozen. Where `2026-10-17-the-waos-project.md` differs (no native build of programs, remote machines last, this project's crates and work order), that design wins. Its interface sketches are rough: each is designed with the lead before it is written. Paths in it are the experiment's.

**Decisions taken (2026-10-16).** Settled with the lead, one question at a time. The lead set the goal: the first version works on the major platforms, installs programs, and has its internals ready for custom IO; the feature set was settled before anything else. The lead took these:
1. **The platforms are macOS, Android, iOS, Windows and Linux,** built in that order: the two phones test the architecture most (Android's new frame path, iOS's interpreter), and Windows and Linux are mostly more of the same.
2. **Programs are installed from package sources,** which a developer publishes to with no service of ours: a GitHub repository's releases, or an `index.json` hosted anywhere. A `.wapk` is signed, and an update is the same id at a newer version from the same publisher, as Android's rule is.
3. **Programs are apps of their own wherever the system allows:** on macOS through a small window process per running program, on Windows, Linux and Android through an identity per window or per task in WaOS's one process, and as tabs on iOS, which allows nothing else.
4. **Programs can do what they do today, and networking, the file picker and dropped files, menus, notifications, opening links and files, audio out, the microphone, the camera and video playback.** Accessibility is not in the first version; it is a known gap, since it will change the views interface when it comes.
5. **Custom IO is ready inside WaOS:** files, processes and networking each behind a provider trait kept in the shape of its WIT interface, served by this computer and by SSH machines, and object stores as a second kind of storage. Providers written as components are for the formal version.
6. **On iOS, WaOS runs from developer builds,** where it installs programs as everywhere else. The App Store forbids downloading code that adds features (guideline 2.5.2, which notarization in the EU applies too), so App Store distribution is not a goal for now.
7. **Programs are written with the repository's own commands.** A command-line tool for writing, running, packaging and publishing programs is for the formal version: this version is an experiment.

Settled along the way, as the proposer's defaults the lead accepted: WaOS's own UI gets only what a feature needs to be used (a permission prompt, a list of sources), and the phone gets one way to pick a machine, enough to prove IO on another machine from a phone; the rest of `2026-09-26-remote-ux.md`'s phone design waits.

Written against wasdk at `a78fb48`, where WaOS had changed little since 2026-09-27.

## Where WaOS stands

| | the first version | today |
|---|---|---|
| Platforms | macOS, Android, iOS (developer builds), Windows, Linux | macOS. Android's frame path ran on the emulator with no screen, iOS's engine in the simulator; Windows and Linux not started |
| Installing | package sources, signed `.wapk`s, updates | a `.wapk` file installed and uninstalled on macOS |
| How programs appear | apps of their own; tabs on iOS | windows under WaOS's own Dock icon; tabs in a phone-sized window on the Mac |
| What programs can do | today's interfaces and the additions above | display, views, windows, fonts, text input, the clipboard's text, lifecycle and quitting, `/data` and `/cache`, granted files, processes in terminals |
| Custom IO | files, processes and networking behind WIT-shaped traits; this computer, SSH machines, object stores | files and processes behind traits; this computer and SSH machines |
| Writing programs | the repository's commands | the same |

## The work, in order

Each step builds and passes on its own; the deepest unknowns come first. `2026-10-17-waos-v1-interface.md` revised this order on 2026-10-17, folding in the interface and adding workers and reshaped processes.

1. **Signed packages, updates and package sources**, on macOS first: the format, checking a publisher, GitHub and `index.json` sources, a list of sources in the library.
2. **Networking**: the provider trait, this computer's and SSH machines' providers, the grant, the interface, a probe.
3. **Android**: Inset's native surfaces there, WaOS's Android app, installing from a source, lifecycle and freezing on a phone.
4. **iOS developer builds**: Inset's native surfaces there, WaOS's iOS app, the interpreter.
5. **Apps of their own**: the macOS window process (frames, input, text input and menus across processes), and Android's task per program.
6. **Grants made while a program runs**: the file picker and dropped files, on the three platforms built by then.
7. **Sound and devices**: audio out, the microphone, the camera, video playback.
8. **Menus, notifications, opening links and files.**
9. **A second kind of storage**: object stores.
10. **Windows**: its compositing, an identity per window, every capability.
11. **Linux**: the same.

## Left out

- Accessibility: a known gap in `DESIGN.md`, since it changes the views interface.
- For the formal version (`docs/formal-version.md`): the authoring tool, App Store distribution, programs as web content on iOS (which 4.7 would allow as HTML5 mini apps), providers as components, gamepads and sensors, the phone's full design for machines, and polish in WaOS's own UI.
