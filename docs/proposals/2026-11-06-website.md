# WaOS's website

**Decisions taken (2026-11-06),** with the lead, one question at a time; the site is not built yet.

1. **Each project has a site of its own, in its own repository** (2026-11-06): WaOS's in this one, Inset's in Inset's, as `valo-site` lives in Valo (github.com/seedeai/valo, `packages/valo-site`), so a guide changes in the same commit as the code it describes. Not one site assembling both repositories' guides, whose copying between repositories is more than two sites cost.
2. **The site is Fumadocs, as `valo-site` is** (2026-11-06), with its `llms.txt`, `llms-full.txt` and every page also as Markdown, so an agent reads the guide in a few fetches instead of the source.
3. **Its pages** (2026-11-06): `/`, what WaOS is, with a short program and how to run it; `/concepts`, the program, view, window, host, capabilities and permissions, on one page; `/start`, installing, making a program, running it and packaging it as a `.wapk`; `/guide/<topic>`, a page per capability, each what it does, a short example and where a platform lacks it; `/reference`, the WIT from its doc comments and the SDK's Rust documentation; `/llms.txt`. No landing page: the site opens on its first page.
4. **One piece of art, and nothing else decorative** (2026-11-06): a strip of fine lines bending into a slow wave above the name on `/`, drawn live on a plain canvas by a few lines of the page's own script, with no library to download (amended 2026-11-08: not `valo-web`, whose download the strip does not earn). Not type alone, nor a drawing of windows.
5. **The first line is for everyone** (2026-11-06): "The platform agents build apps on. Fast, light, secure by default." How it works, WebAssembly and WebGPU among it, comes after. The lead measured what "fast" and "light" claim. Its action is downloading WaOS.
6. **The second section is for whoever builds apps, with no label saying so** (2026-11-06): one line on WebAssembly and WebGPU with the whole platform beneath them, then what a program has, named only, each linking to its guide (windows, WebGPU, compositing, media players, cameras, audio, menus, file dialogs, notifications, clipboard, processes, network), and where it runs today. It confirms what the platform has against the web's subset; the guides explain. Its action is copying what an AI agent is given to start building an app.
7. **What an agent is given is a one-line prompt pointing at an agent's playbook, `/agents.md`** (2026-11-06): installing WaOS, making a program, running it, and where each guide is, written for the agent to carry out itself, as Vercel's `/get-started.md` is (`2026-11-06-website-research.md`); the same page ships as a skill. Not a skill file to install, which fewer agents take.
8. **After the two sections, one sample: the smallest program, in Cupertino, and the command that runs it, beside a phone-shaped frame running Waft's Cupertino gallery live on the web** (2026-11-08), the gallery already deployed for Waft, so no other demo is built or kept up; the frame is named as the gallery, a whole app, so it never passes for the five lines beside it. Not a still, nor a demo of its own to deploy and maintain.
9. **The site is `waos.app`; the download waits for a release** (2026-11-08): the download link is a placeholder, `about:blank`, until WaOS is released once apps on the platform feel stable, and so is the GitHub link, until WaOS's own repository is public. `waos.dev` is the lead's too.
10. **The site's code is `packages/waos-site` in WaOS's repository** (2026-11-08), as `valo-site` is `packages/valo-site` in valo's, `packages/` leaving room for other JavaScript packages.
11. **`/agents.md`'s routine is tools, make, look things up, build and ship; running and checking the app is a section of its own, for when the agent wants to see it work** (2026-11-11): `cargo waos new` writes WinUI, which works on desktops and phones, and `--template cupertino` is for an app meant for phones alone (the project's decision 59); looking things up names Waft's page, the guides, `llms-full.txt` and docs.rs; trying it is `cargo waos run`, `screenshot` and input at a point (the project's decision 60). Not run and check as steps every app goes through.
12. **A frameworks section, `/docs/frameworks`, opens with Waft's page, the guide to Waft for WaOS apps: its widgets, state, menus, shortcuts and windows** (2026-11-11), since Waft is WaOS's main framework and finding its API by reading its source took most of the agents' time (`2026-11-06-building-apps-research.md`); other frameworks, GPUI's or Bevy's adapters among them, get pages of their own there later.
13. **A guide page is one capability, for every framework: what it does, a short wasdk example, "In Waft" with Waft's example, where it is missing, and its interface** (2026-11-11); the two examples say different things, what the platform gives and how Waft gives it, so each fact has one home. Waft's page holds Waft's own model (widgets, state, layout, pages, the kits, theming, shortcuts) and links to the guide for each capability rather than repeating it; a later framework's page holds its model, and a guide page gains a line for it only where its adapter differs.
14. **The site runs on Vercel, built there from the sources** (2026-11-11), keeping the site's search and the middleware that answers an agent asking for `text/markdown`. First Cloudflare Workers through the OpenNext adapter, where Waft's gallery runs, then given up the same day: the Worker came to 3.97 MB compressed, past the free plan's 3 MB, and its 23 MB went up from here at about 90 KB/s on every deploy, where Vercel builds from the uploaded sources.
15. **The home page is three sections, each with one job, replacing decisions 5, 6 and 8** (2026-11-11): it catches the reader, with "Apps on demand. Built by your agent.", the two actions (Download for macOS; Have your agent build an app, which copies the prompt) and the wave, now the page's three colours and filling the first screen's lower half; it says what WaOS is, "The home for apps your agent builds. Built on WebAssembly, so an app written minutes ago is safe to run.", with four cards, each a small drawing over its words (every permission granted by the user, light on memory, one app on every platform, real apps); and it invites whoever builds, "Or build one yourself", WebAssembly and WebGPU for anything from a to-do list to a video editor, with the three commands, the docs' four doors and the platform's capabilities, each with an icon and its guide. Calm, with no line that says nothing, in the manner of Apple's product pages: one statement a section and short words beneath. The long sample and the phone's gallery go; the memory card's nine to one is drawn by eye until the lead's measurement replaces it.
16. **The first screen's words, icon and second action** (2026-11-11, amending 15): the statement is "Apps on demand. Secure. Fast. Efficient.", since the second action already says an agent builds the app; WaOS's icon, three waves in the page's colours, one behind another, rising in a white app tile, stands above it, in the header and in the browser's tab; Download carries an arrow; and the second action reads "Build your app with" and the name of an agent the reader may already use, each sliding up after the last, as text in its maker's colour (Claude Code, Codex, Cursor, Gemini CLI, Grok Bot; real logos only where a brand's rules allow), still while the pointer is on it or the reader asks for less motion. It opens three steps, get WaOS, give your agent the prompt, which it copies, and the app opens in WaOS, in place of a button that copied and showed nothing.
17. **The docs' pages** (2026-11-11): the sidebar holds the pages alone, Start first, then Concepts, Guide, Frameworks and Reference, the last closed until opened; a page opens with its title and one line saying what it is, the Markdown controls small beside the title; a section's own page (Guide, Frameworks) shows its pages as cards, each with its sign, name and line, the signs the home page's; and a guide page's parts are headings, With wasdk, With Waft, Where it's missing and Interface (amending 13's "In Waft"), so each has its list of what is on the page, its code's comments on lines of their own.
18. **Platform-aware downloads on a static home page, and a plain 5-minute edge cache for releases** (2026-11-22): `/` stays statically prerendered so high-volume traffic is served directly from Vercel's CDN; static HTML renders a neutral `Download WaOS` button with all four platforms (`macOS`, `Windows`, `Linux`, `Android`) linked below, and the client specializes the primary button, the agent modal's platform order, and the quickstart shell tab (`sh` vs PowerShell) to the visitor's OS after hydration (leaving iOS and unknown systems on the neutral button). `/api/latest` and `/download/<platform>` drop `stale-while-revalidate=86400` and Next.js's `revalidate` Data Cache — which together handed visitors 24-hour-old redirects after a release — in favor of `dynamic = 'force-dynamic'`, `cache: 'no-store'` on upstream fetches, `Cache-Control: no-store` to browsers, and `Vercel-CDN-Cache-Control: public, s-maxage=300` for a plain 5-minute edge cache; `latestRelease()` reads `/releases?per_page=5` so a release whose platform jobs are still uploading never 404s the remaining platforms.
